# Programmes content package

## Purpose

The private `/publication-review/programmes-content-package` workspace creates
one management-approved content handoff for:

- the current relationship between CBSE Classes XI-XII and any separately
  operated Junior College;
- streams, subjects, affiliation or recognition, eligibility, fees and the
  admission procedure for each current pathway;
- the operator, curriculum, timetable, faculty summary, fees, facilities and
  results-publication decision for JEE, NEET and CET preparation;
- exact approved public claims, requested media records and navigation
  placement; and
- opaque controlled evidence references, role-only approval attribution and the
  approval period.

The output conforms to `content/programmes-content-package.schema.json`.

## Operating order

1. Confirm the institutional model from authoritative current records.
2. Review programme facts, fee wording and admissions wording with management.
3. Decide whether JEE/NEET preparation is offered and identify its exact
   operator. Do not infer this from old WordPress pages or supplied artwork.
4. Approve exact public claims and choose only the media records requested for
   later placement.
5. Record at least two opaque controlled evidence references and the approving
   role. Keep minutes, certificates, fee schedules, identities, signatures,
   pupil data and source paths outside the repository.
6. Complete the final confirmation and download the JSON package.
7. Retain the package in the controlled system for implementation review.

## Boundaries

The browser form has no server action. It does not post or persist form data,
read evidence, grant approval, update the approval manifest, approve media or
documents, create public pages, activate navigation or deploy the website.

The selected media records remain governed by their existing independent media
and claim approvals. The related claim records are:

- `claim-junior-college-status`;
- `claim-xii-science-results-2025-26`; and
- `claim-engineering-medical-guidance`.

After the package is reviewed, a separate implementation change may populate
the public programme routes. That change must recheck the package academic year,
approval period, evidence references, current manifest decisions, document
bindings and exact approved media before changing public output.
